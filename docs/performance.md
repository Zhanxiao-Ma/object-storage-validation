# 性能测试

一次执行全部文件操作，自动测试单并发和配置的多并发。无需选择性能模型或档位。

```bash
cp examples/performance.json local-performance.json
# 填写存储 endpoint、region、bucket 和 SDK 启动命令
python3 -m osv run local-performance.json --mode performance --output results/performance-001
```

`--mode all` 同时运行功能测试；`normal/complete` 只决定功能范围。

## 操作与默认数据

| 操作 | 默认用例 |
|---|---|
| 获取文件信息 | HEAD |
| 读取整个文件 | 4 KiB、4 MiB、64 MiB |
| 读取文件区间 | 64 MiB 文件，读取头部、中间、尾部的 64 KiB、1 MiB、4 MiB |
| 写入整个文件 | 4 KiB、4 MiB、64 MiB，写入独立 Key |
| 分片上传 | 32 MiB、64 MiB 文件，5 MiB、16 MiB 分片，包含短尾分片 |
| 列举文件 | 完整列举 10、1001 个对象，包括跨页列举 |
| 复制文件 | 4 KiB、4 MiB、64 MiB，服务端复制 |
| 删除文件 | 单个删除；批量删除 1、100、1001 个对象 |

每个操作由 SDK 驱动实现。分片上传从创建到完成合并算一次文件操作；跨页 LIST 和拆批 DELETE 也按完整操作统计。分片协议步骤在驱动内执行，不由控制进程逐次调度。每个并发通道使用一个持久 SDK 进程和客户端；并发度表示同时执行的文件操作数，单个文件的分片按序上传。

## 计时与校验

- 准备对象、生成输入、计算预期摘要、校验和清理均在测量窗口之外。
- 输入是普通磁盘文件，读取结果也输出为文件；文件操作延迟包含驱动及 SDK 的本地文件 I/O。吞吐还包含调度和进程通信。报告不把这个指标称为纯网络耗时。
- 所有读、写、复制和分片上传结果均校验长度与 SHA-256；写入后实际 GET 校验。LIST 比较完整对象集合，删除后检查对象确实不存在。校验失败不计入有效吞吐。
- 每个大小、区间位置、分片大小和并发度单独输出成功/失败次数、p50/p95/p99、MiB/s、操作数/s或对象数/s。预热排除在正式统计之外。
- SDK 目标交错运行，逐轮平衡先后顺序。报告保留逐轮吞吐和 CV；CV 超过 20% 或测量窗口不足时，对比结论为 `inconclusive`。

默认 8 轮、每轮至少 32 次操作，预热至少 4 次。真实 SDK 的读取、写入、复制及分片上传每组累计测量至少 5 秒，分成有界窗口；窗口之间校验和清理，累计吞吐只使用实际测量窗口。自动延长最多涉及 4096 个对象或 16 GiB 逻辑数据量，达到上限仍不足 5 秒则明确标记。请求数不足并发度时至少执行一次每通道操作。

输入文件不默认放入内存文件系统。各窗口完成后立即验证并清理输出文件；失败上传尝试取消，清理错误保留在报告中。

## 可选参数

常规只需配置目标存储。需要改变负载时修改 `workload.requests`、`concurrency`、`rounds`、`warmup_requests`，或 `workload.files`：

```json
{
  "sizes": [4096, 4194304, 67108864],
  "range_object_size": 67108864,
  "range_sizes": [65536, 1048576, 4194304],
  "multipart_sizes": [33554432, 67108864],
  "part_sizes": [5242880, 16777216],
  "list_counts": [10, 1001],
  "delete_counts": [1, 100, 1001]
}
```

单个文件最多 256 MiB，并发文件数据量不超过 1 GiB。这些参数调整数据量，不控制操作是否执行。旧版多对象/重复访问/读取模式调度已由这套文件操作矩阵替代。`objbench`、`read`、`multipart` 的旧参数不再决定性能用例，迁移时改用 `files`。

同语言、同存储的 AWS SDK 与厂商 SDK 可直接配对；两个 SDK 都使用 S3 协议也允许比较。使用 `comparisons` 中的 `s3`、`native` 指定左右目标 ID（字段名为历史命名），并确认相同存储与网络条件。

驱动缺少操作时，报告列出具体未执行用例及缺失能力，并继续运行其他操作，不将未执行项当作通过。
